# Independent unseen-set authoring record

The six YAML files contain 100 newly authored Chinese requests and PostgreSQL Gold statements. The fixed quotas are 20 / 20 / 16 / 22 / 10 / 12 for basic single-table, aggregated single-table, time window, multi-join, deep multi-join, and business semantics.

The author had a fresh agent context, did not participate in earlier production tuning or question writing, and used only actual PostgreSQL business schema/data plus the three explicitly permitted domain-contract resources. The frozen candidate identity is copied into `authoring-manifest.json`; no candidate prompt, implementation, historical model output, audit, or tuning-history content was consulted. Permitted domain metadata includes historical illustrative prose, so the provenance boundary is the declared allowlist, not an assertion that those resources lack historical references.

Old evaluation, holdout, benchmark and fewshot files were parsed by a separate exact-overlap program only. The program emitted counts and new-set IDs, never old question text, SQL, answers or old IDs. Its comparison normalizes NFKC, lowercase, Unicode punctuation, separators and whitespace. Zero exact overlap does not prove zero semantic overlap; manual semantic comparison against old examples was deliberately excluded by the independent-author protocol.

All final Gold statements were actually executed as `text2sql_ro` with `BEGIN READ ONLY`, an 8-second local statement timeout and rollback. Execution evidence verifies `current_user=text2sql_ro` and `transaction_read_only=on`. The full result rows, stable result hashes and per-case execution status are saved in `gold-dry-run-results.json`; the aggregate report is `gold-dry-run-summary.json`. Execution wall times include command/container overhead and are not model or SQL-only latency measurements.

Draft validation identified one timeout; an equivalent Gold plan using a pre-deduplicated return-identity set passed its targeted rerun. Five draft conditions produced empty results and were replaced using actual source-data distributions so that the sealed final set has no empty-result cases. One relation request was expanded to include the tracking domain. These are pre-seal authoring changes based solely on domain contracts and source data, not candidate answers or failures. Previous executions remain in each case's `previousAttempts` evidence. Final validation is 100/100 passing, zero results over 500 rows and a maximum result of 207 rows. There were 107 total Gold executions, including the preserved initial timeout.

The set covers all 37 business tables across trading, customers/membership, products, marketing, fulfillment/inventory, service, finance and search. Result contracts state physical identities, dimensions, status scope, monetary components, time boundaries, tie-breaking, NULL treatment and ratio units where relevant. Requested Top-K statements have stable ties; complete dimension aggregates are not truncated merely to add a LIMIT.

Following the independent reviewer's targeted feedback, one calendar-overlap contract was tightened to require a valid start/end interval, and the matching Gold predicate was added. Only that case was rerun; the corpus remains 100/100 passing with no over-500 or empty results. Total actual Gold executions are now 108, retaining all prior attempts. The author has not self-approved the independent review; the refreshed author seal continues to report `independentReviewerCompleted=false`.

The human-directed frozen-runtime compatibility requirement subsequently tightened the output ceiling from 500 to 200. Exactly one accepted draft returned more than 200 rows. That request now explicitly selects the highest-stock 150 groups from known stock sums with stable ordering by its complete grouping dimensions; its Gold was changed to the identical selection. The original six YAML files and author evidence are preserved in `pre-maxrows200-original/` with a snapshot manifest. Only the changed Gold was rerun, producing 150 rows. All final results are at most 200 rows (maximum 174), and all 100 Gold statements pass; cumulative Gold execution count is 109. No runtime, production code, model, quota or candidate output influenced this selection beyond the explicitly authorized 200-row compatibility ceiling. Independent review of the updated corpus remains pending from the author's perspective.

Provider calls: 0. External LLM calls: 0. Credentials read: no. Database writes: 0. Production/original dataset edits: 0. Git commits by this author: 0. Writes were confined to the new six YAML files and this report directory.

This is a shared filesystem without enforced OS isolation. Independence is therefore procedural, not a security boundary. The author did not act as the independent reviewer; a separate fresh-context reviewer must review the sealed set before the candidate/baseline run.
