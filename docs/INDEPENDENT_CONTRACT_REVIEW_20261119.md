## 4. 技术与设计导读

以“有效订单数、下单人数、客单价”为例：先在orders形成98207笔有效订单，再沿customer_id读取自然人身份得94990人；商品明细先按order_id聚合金额，LEFT JOIN回完整订单，金额除完整订单数得到160.23。原参考INNER JOIN明细先删了8单，三列都受影响。记录身份、自然人身份、金额事实三条来源不能混成一个集合。

核心抓手是新上下文审查、真实PK/UNIQUE/FK检查、只读快照查询与构造反例。汇总器验证输入SHA、题号覆盖、来源声明和生产源码树，再比较旧结论；不是投票打分。本次没有改检索排序，directHits/关系扩展/桥接来源、0.4衰减及最多2张补桥表均不变。

替代方案是直接按旧参考追分或覆盖旧Gold；两者都会混淆模型能力和基准修订，因此否决。面试问“参考改对后涨分算优化吗”，答：不算，必须将同一冻结模型输出按新旧参考重算，或在同一新版本上比较基线与候选。问“多agent是否等于外部盲测”，答：不等于，流程隔离有用，但共享文件系统不提供操作系统级保密，已见题也不再未见。

本批无用户必须操作的事项。需要理解的仍是：数据的三个来源集合、外部模型新增花费为0、错误落在参考/契约层而非自动归为模型层。
