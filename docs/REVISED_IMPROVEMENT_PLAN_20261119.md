# 重新规划：保留工程成果，恢复质量与速度

日期：2026-11-19。状态：**方案已形成，实施及新付费批次尚未启动**。本方案替代此前“整体回到p9后再加修复”的推进建议；不覆盖历史计划、分数、停止记录或冻结协议。当前任务只交付方案，供应商调用为0。

## 1. 这次改进要解决什么

p21正式三轮为86/86/84，均值85.33%，尚未达到89%。同版本参考下，p9安全回补版为84/82/85，均值83.67%；三轮P95均值由13.642秒升至15.005秒，超时合计14→23。因此停止p21整批发布是合理的，但没有证据说明每项修复都无效。

新路线是：**保留安全与工程基础，先消除确定性误拒，再减少重复输入，最后用有限次数证明整体验收是否通过。** 不继续把每个失败都写成一条全局提示规则。

原目标保持：阶段2正式正确率至少89%，相对冻结比较基线退步不超过2个百分点；阶段3三轮P95均值低于8秒、每100题完整成本不超过¥0.30。阶段2还须满足目标失败案例至少修复一半等原要求。中间恢复速度不能冒充项目最终完成。

原阶段3模型、路由、思考模式等性能专项继续处于用户要求的暂缓状态。本方案中的输入整理用于控制阶段2修复的附加代价，不自行切换模型、推理设置或恢复阶段3实验。

## 3. 执行顺序与每步出口

### A：先固定验收口径与版本，不调用模型

1. 固定当前工程来源、p21及p9安全回补JAR、依赖、运行参数和数据库数据身份。记录实际源码树及未提交差异，不能只写一个Git提交号。
2. 根据已有公开审查，一次性处理排序、周覆盖、未知注册月、默认地址覆盖等未决口径。明确请求优先；题面无法唯一决定的范围，在新参考中明示，不让系统猜，也不靠现库碰巧无反例来定规则。
3. 已冻结V3保持字节不变。确需修正时另建V4及逐条Errata，保留100条开发/100条正式的分层与难度，分别记载题面、SQL、评分变更原因；未参与候选实现者审核。不得根据新候选输出修改答案，不放宽89%或删除难题。
4. 原阶段2目标固定为T4-001（身份）、T3-002（形状）、T6-003（单位），严格至少2/3，保留[原判据](STAGE2_REGRESSION_PROTOCOL_20261117.md)。预登记它们与新开发100题的映射：原题及原判据均完整保留者，使用最终选定候选的唯一开发响应作判断；题面已改写者不得替代原目标，预登记原题各一次确认，最多3请求，计入总上限。这组确认在开发通过后、正式之前完成，任一题不重复、不从正式三轮择优。逐题保留新SQL、结果与归因；历史专项2/3不自动继承。若原目标与新产品契约有冲突，A阶段先记录并裁决，不能静默换成容易题；原严格判据和历史失败均保留。
5. 建立公开题的输入清单：系统规则、DDL、指标、示例、来源、字符数，以及已有首答/纠错/校验/DB分段记录。已有266组首答输入约+82%的证据只用于定位，不能当作逐条修复因果。

**交付物：** 版本清单、契约与Errata、原目标案例映射、输入及慢请求归因表。原Gold200须仍可执行；新参考另外执行校验，不能拿原200自检代替新参考正确性。

**出口：** 独立审查确认题目、产品契约与评分一致后，才能冻结候选。若契约仍矛盾，停止在这一层，不付费追分。最多两次成套审查提交，第二次仍不成立就交付未决项并停止本轮。

### B：单独完善完整业务目录校验，不增加模型输入

**唯一机制：** 生成仍使用原检索上下文；合法性校验使用完整、受授权的业务目录。检索遗漏不能被误当成物理表列不存在；完整目录也不等于数据库中任意对象均可访问。

现有草稿的31项合成检查与19项旧校验器检查只算组件证据。实施时补齐：

- 最终执行、缓存命中、纠错与回退、编排替身，以及工具SAMPLE/CHECK/EXPLAIN的目录来源和权限边界。
- 真表未检索、真列被裁剪、别名/限定列的正例；虚构表列、内部表、跨schema对象等负例。
- 目录空、缺失、异常时返回目录不可用，数据库执行为0，不触发额外模型纠错或绕过校验的回退。
- 真实只读DB和受保护HTTP入口的相关集成；确认鉴权、费用预留、超时和会话收尾未退步。
- 相同公开请求的实际首答输入逐字不变；完整目录不注入Prompt，不改变TopK、0.4衰减或桥接2表上限。

**交付物：** 单独补丁、覆盖矩阵、相关集成报告及输入一致性报告。最多两次成套审查提交；任一新增危险放行均拒绝该补丁。

**出口：** 全部边界通过后固定为本地工程基座B0。此时只可说“误拒修复在已验范围成立”，不能说准确率、P95或整个阶段已经提升。未通过就不把它带入后续候选；本轮停在此处，不临时叠加日历/澄清补丁绕过。

### C：在B0上准备一个输入收敛候选，先免费筛选

本轮限定两条路线，分别从同一B0出发，不能把第一次付费失败后的一串临时规则继续叠进第二候选。

| 顺序 | 唯一主要机制 | 必须保留的语义 |
|---|---|---|
| C1优先 | 合并系统、指标、DDL和示例之间的重复说明；删去无信息增量的重复文本 | 正确规则的全部适用条件、显式请求优先级、分母、事实身份与时间/NULL边界 |
| C2备用 | 业务定义按请求需要提供；识别不确定时保留原规则 | 否定、复合请求、同名指标、跨表依赖及明确表达均不得漏规则；通用安全保护始终提供 |

C1通过后直接选择C1，不再付费试C2。C1失败时，只有C2自身的本地证据成立才允许进入一次开发筛选。第二路线不是更换模型或缩短15秒预算。

付费准入前须满足：公开200题总输入字符相对B0至少减少20%，输入字符P95不增加，逐题变化可解释；未适用请求保持原输入；独立边界无新增危险放行、明确请求退化或必需规则缺失。20%是本轮事前的投入筛选条件，不意味着耗时必然降低20%，字符数也不冒充Token。

**交付物：** 输入前后差异、规则覆盖与依赖表、独立反例审查、相关工程/HTTP检查、一次最终全量构建与原Gold200自检。小编辑只跑相关检查，最终候选固定后再集中做全量检查。

**出口：** 无实质输入减少或契约保真失败，不花钱跑题。每条路线最多两次本地成套审查提交；两条路线都无合格候选，本轮结束。

### D：冻结候选后，才进入有限付费验证

只新建协议和输出目录；旧控制器、冻结协议与原U_C目录不改、不续跑。付费前登记并检查所有门槛和调用计数，工具必须能执行下面的新流程；不能仅靠文档提醒。

| 层次 | 规模 | 进入下一层的条件 |
|---|---|---|
| 开发筛选 | 每候选100题一次，最多2个候选 | 沿用正确≥71/100、深层≥4/10、业务≥6/13、超时≤9；额外要求独立危险放行0，C阶段输入收敛与契约保真已通过。失败不进入正式或未见 |
| 原目标确认 | 仅最终选定候选，复用已登记的开发响应或补最多3个原题请求 | 按原严格判据至少2/3；未通过即结束本轮，不进入正式，不另选候选续跑 |
| 正式确认 | 仅1个候选；p9对照与候选各100题×3轮 | 同时满足下一节第1—4项正式门槛；失败结束本轮，不换候选再跑正式 |
| 独立未见 | 仅正式全部通过后；同一对照/候选各100题一次 | 候选相对对照正确率退步≤2pp，独立危险放行0；记录P95、超时、分层与完整费用。不用未见挑第二候选 |

开发门槛只用于筛掉明显不合格候选，不证明整体已改善；不同分布的开发集不直接套用正式89%门槛。开发仍报告P95和分段耗时；正式另有严格的恢复护栏。88/8/8/9是旧p21的V3开发记录，不是新V4成绩，也不据此宣称正式89%一定可达。

**顺序预登记：** C1开发；仅C1开发未通过且C2本地合格时跑C2开发；选定者固定，先完成原目标确认。正式顺序为B1、F1、F2、B2、B3、F3，B/F分别指p9对照/最终候选的运行编号，避免与C1/C2路线混淆。只有正式全部通过，才运行新未见B、F两轮；这是新协议事前的费用止损安排，不追改旧协议的“正式后无条件完成未见”。

同一版本、同一层仅登记并执行一个批次，不重跑等高分。时段不足只等下一空闲窗口；已开始而中断的轮次保留为中断，不静默补题、删除或重放。证据/指纹漂移立即停止，不能为了补齐报告再送模型请求。

## 4. 如何证明比现在更好，而不是换一个宽松基准

**最终效果对照固定为p9安全回补版**：`3c0bda099c08183ff3e3b4607bd0a071158fc630`，JAR SHA256 `a89dbd431263f0c9356510d71a5dd90fdcd6e0b3ab806ce9e3fdd16cf1121a8b`。在新冻结参考上，与最终候选同期重测三轮。当前工程来源为p21，历史p21包SHA256 `e8a3db8efba97e675432b995018b23b016088604cc446513c2d84f85703fe764`。

候选工程始终保留新保护。p9仅在已登记的本机隔离评测环境作为参照运行，其缺少后来鉴权/会话等功能的边界继续公开；protected入口另用免费集成验收。不得把新核心加旧提示词称为“原p9”，也不得继承历史91%。

与B0的逐字输入/SQL回放/边界比较用于判断局部机制；正式的p9与候选比较用于判断整套版本净效果。两者不是同一个比较。未额外做同工程的真实模型配对时，不声称已证明某条单项规则带来多少正确率或延迟收益。

阶段2必须全部满足：

1. 同期同参考，候选三轮平均正确率≥89%，相对p9同期均值退步≤2pp；原目标失败案例至少修复一半，明确请求/澄清与契约检查均通过。
2. 候选三轮P95均值≤p9同期均值，**并且≤13,642ms**；三轮超时合计≤p9同期合计，**并且≤14**。固定的历史恢复边界防止双方都变慢后把14.9秒包装成恢复；13.642秒仍只是中间护栏，不是最终目标。报告全部每轮值及100题完整分母。
3. 新增独立危险放行为0；相关安全/运行集成、原Gold200及新参考校验通过。工程测试数量不折算为业务正确率。
4. 调用、首答/纠错、输入/输出Token、缓存和费用单列。按相同价格口径比较费用；用量未知必须报告，不能按0计算或以已知费用下界宣称成本通过。
5. 正式通过后还须完成新未见对照，满足预定不退步与安全要求；否则只保留“已见集通过/泛化待验或失败”，不关闭整体阶段。

原11.060—11.799秒来自旧参考/批次，保留为历史表现，不与新参考直接拼接。最终仍须在阶段3取得P95<8秒、准确率相对退步≤2pp、每100题完整成本≤¥0.30，才能宣称性能与费用目标完成。无法取得可靠完整用量或费用上界时，该成本项为待验，不为补齐未知而重跑。

### 失败后做什么

- 本地一条路线两次成套审查仍失败：停止该路线，保留反例与可复用组件。
- 开发失败：该候选退出；最多另试已独立准备的另一机制，不能同版重跑。
- 正式或新未见失败：本轮结束，保留全部分数、失败、成本与未知；不再追加第三候选。
- 最终结论只能是“本轮路线与约束下未验证出可发布方案”，不能夸大为目标永远不可能；若只完成局部修复，明确标注局部成立而阶段未过。
