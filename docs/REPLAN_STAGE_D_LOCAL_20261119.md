# D本地接入与技术设计导读

本包是评测工程接入，不是模型正确率、生产延迟或完整费用通过。A/B/C已接受，C1只做输入收敛；D付费须有匹配固定plan的独立审查，并再次核官方空闲时段。阶段3专项与旧U_C仍暂停。

## 具体请求怎样流动

以公开开发T1-002“2018年有多少笔订单”为例：控制器取冻结题面，经本机HTTP进入原p9或C1 JAR。Java照常检索、生成提示词；模型地址固定为本机转发器。发送门禁核同题首答/纠错身份、15秒父请求期限、空闲时间、每题最多两次、全批估价配额后，先持久化唯一permit。转发器随后才可能把请求交给官方。

免费接入用本机替身返回冻结SQL，真实Java校验并在只读库执行，HTTP当时返回`columns=["count"], rows=[["54011"]], truncated=false`。控制器先保存原HTTP字节和SHA，再严格解析、保存答案并核预算。共同Java评分桥只比较这些当时返回的行，不执行候选SQL来补造答案。免费替身给出正确SQL不代表模型能生成正确SQL。

供应商返回的usage由转发器直接交到账本，和Java当时的HTTP预算快照各自保留。应用可能已返回超时，而转发器稍后才读到完整usage；这种情况要单列晚到费用，不能修改已返回答案，也不能把应用快照里的未知偷偷改成0。

## 核心组件与身份防线

`run_replan_stage_d.py`负责固定计划、阶段转换、双层时段门禁、跨版本/进程共享发送账本与原始HTTP证据。`replan_stage_d_proxy.py`负责单次直连固定官方端点、绝对期限与严格分帧；`StageDScoringBridge`负责只读参考准备和实际结果评分，调用A冻结原字节评分器。

题目凭据是`dataset + id + questionSha256 + goldSqlSha256 + policy`；调用凭据是`round + questionId + attempt + token + requestBodySha256`；permit和completion分别不可覆盖。逐题必须满足发送许可数≤应用modelCalls≤2。调用开始、传输尝试、HTTP确认响应、用量已知/未知是不同事实，不能扁平化成一个“调用成功”计数。

本机制没有模型打分权重或TopK删题：100道完整分母，P95取排序后ceil(0.95×N)，失败不能被删除。检索原有TopK8、关联衰减0.4和桥接上限2表保持冻结，D没有调它们。已测独立危险边界为0新增，不是所有SQL安全性的形式化证明。

全批估价配额¥1.00，单调用预留¥0.10。完整usage满足prompt=hit+miss、total=prompt+completion后，费用为`(0.02×hit + miss + 4×completion)/1,000,000`元。未知用量持有全部预留，版本/轮次/进程切换不重置。字节数+1024只是配置估值，不能证明供应商Token或账单硬封顶；超过估价/预留时记录真实值并停止。

## 验证数字与失败保留

控制器首次19项为18通过、1项测试夹具重复Q1触发正确防重；只改夹具后该项1/1通过。合并留证、permit核对和费用对账改动后，23/23通过。代理原20项本地检查通过；随后chunked/重复JSON专项13/13通过，不把不同版本结果伪装成一次33/33全量。

第一次跨JAR接入在p9分块请求体处失败，门禁和上游均未进入。第二次C1健康检查漏带凭据；第三次虽补凭据，控制器错用Bearer，而受保护入口要求Basic，仍未进入题目请求。三个目录全部保留。修复只增加合法chunked支持、严格重复键边界和正确的Basic凭据传递，没有修改模型候选。最终24项控制器检查后，仅补跑鉴权编码相关1项并通过，不能改写前轮。最终固定批次接入结果由`batch-1/preflight.json`记录；每侧只有2个实际HTTP答案，另外98份明确标记为合成Gold响应，100/100只表示评分桥接入成立。

## 设计权衡与面试追问

不改原JAR实现共同发送保护，因为改装p9后无法再声称它是原版本对照；也不只靠Java侧启动计数，因为SDK重试、取消和未知用量可能绕过外层统计。保留两个冻结JAR，在共同本机转发层做发送许可和账目。它增加本机转发开销，因此双方同路径计时，不能拿新wall与旧内部计时作逐毫秒因果结论。

问：为什么不能重新执行模型SQL再评分？答：那会掩盖当时执行失败、截断、漏列和超时，破坏端到端正确率。评分桥无候选SQL执行入口，响应原字节、解析答案和评分输入均有SHA可核。

问：¥1.00是不是绝对不会超？答：它是本地准入配额，未知保留全额；供应商Token统计才决定真实费用。未验证的Token估值不能称数学上界，发现越界必须保留真实金额并停止，不能为跑完题数提额。

## 边界与用户需要核对的事

高峰前整轮保留1740秒、每次发送保留120秒再加父请求剩余连接时间；节假日例外不放宽。chunked解码≤1MiB、≤4096块、整个body≤15秒；TE+CL冲突、非法trailer和递归重复JSON键拒绝。发送实际payload还受65536字节更紧上限。解析异常、身份漂移、预算不足和中断都留证停止，不补题/重放。

独立审查通过后也只能先跑唯一DEV_F；开发失败停止，不切C2。正式全过才由未参与实现者准备新未见，根任务不读取封存未见题/Gold。数据库当前可用，无需用户额外操作。用户需要掌握并核对：请求从HTTP到真实行的流转；已知费用与未知预留；失分属于生成、校验、执行、契约还是测量故障。
