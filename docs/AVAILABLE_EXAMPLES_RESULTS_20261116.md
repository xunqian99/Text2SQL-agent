## 2. 实现机制、来源与边界

请求先经过原Schema检索、列剪枝和指标注入，再由 `ExampleSelector` 选择参考SQL示例并交给 `PromptTemplate`。例如当前表上下文只有orders/customers，某个示例需要orders/customers/members：原策略可能因为共同表数2而优先选择它；候选在排序前检查依赖，members不可用便排除，再从合格示例中选择。模型随后生成SQL，仍经过原只读护栏、执行和结果比较；示例SQL自身不会直接执行。

技术抓手是 `ExampleLoader` 沿用JSqlParser经 `TableRecall.expectedTables` 解析出的 `Example.tables`，以及配置 `agent.fewshot.require-available-tables`。默认false，候选true；`FullSchemaProvider` 和 `HybridSchemaProvider` 均传递该配置，生产默认没有改为true。没有新增依赖、修改示例文字或扩大Schema。

设示例依赖为E、当前可用表为C，候选准入条件为 **E非空且E⊆C**，忽略表名大小写。先过滤，再沿用排序：共同表数 `|E∩C|` 降序 → Jaccard `|E∩C|/|E∪C|` 降序 → 示例ID字母序，上限2。没有调整权重，也没有用“缺表降权”让不合格示例再次参与补位。Schema检索的0.4关系扩展衰减与此处Jaccard是不同机制，本轮未改变前者。

来源凭据分别保存：`examplesLibrary` 固定整库示例ID、问题/SQL哈希和依赖；每题的 `defaultExamples/candidateExamples` 记录选择身份与 `missingTables`；`commonContextSha256` 证明除示例外上下文相同；`defaultPromptSha256/candidatePromptSha256` 对应完整首答消息。缓存签名携带策略版本，报告与JSONL保留配置标记；配置标记不能代替实际消息指纹。

空依赖、解析失败、空白依赖均保守排除；CTE别名不算真实表，但CTE体和子查询依赖必须可用。同题示例仍排除，空候选不给示例、不补缺表内容。**表可用不代表剪枝后的列也可用，更不代表示例业务相关、输出契约明确。** 缺表过滤会丢掉有帮助的跨表结构，这也是必须真实对照的原因。

## 5. 超时、观测漏洞与下一步

默认未知调用为T5-002、T5-019、T6-014；候选为T4-018、T4-032、T4-041、T5-006、T5-019、T6-014，均为首调用，终止原因为 `DEADLINE_EXCEEDED`、`budget.stage=MODEL`。T5-019两组消息相同且都超时；T6-014两组示例变化但仍都超时。不能把所有超时直接归咎于示例过滤。

另发现**超时分段耗时的观测缺口**：这些请求 `wallLatencyMs/totalMs` 约15000，但 `generationMs=0`、其他分段也为0。`budget.stage=MODEL` 保留了停止位置，整体预算仍被执行，问题是中断时没有保留已消耗的分段时间；不能据generationMs=0声称“模型没有耗时”，也不能把它直接加入MODEL占比统计。此缺口不改变本轮以墙钟计算的P95与评分，却妨碍进一步瓶颈归因。

下一步仍限阶段3：先修复**在途阶段被中断后的分段耗时记录**，覆盖正常返回、模型超时、数据库超时和线程取消；墙钟、已完成阶段与未完成阶段分别记录，避免重复计时或把未知耗时算0。验收应以可控阻塞测试证明约15秒等待落到MODEL，已完成的检索时间仍保留，且不会放宽总预算或增加调用。完成这项可靠性修复后再决定复杂请求的下一项生成实验，不继续盲试参数，不重新调整评分集。

**为什么不直接把缺的表补进Schema？** 那会同时改变检索、Join上下文和Token，无法隔离示例选择的效果，也可能扩大噪声。候选使用准入过滤而非降权，是为保证不合格示例不能为了凑数进入Top-K；这个不变量不保证模型更好。

**面试追问1：缺表示例从59降到0，为什么还不上线？** 回答应区分输入一致性、模型质量与服务性能。本轮一致性通过，但P95和完整成本门槛未通过；部分被删的跨表示例可能有结构价值，单轮实验又存在输出波动，不能拿一个局部指标代替发布门槛。

**面试追问2：平均更快，P95为什么更慢？** 候选慢请求数量13→9，但6个超时把第95顺位推到约15秒。P95由排序位置决定，不由平均值或慢请求总数直接决定；需同时报告分布、预算停止原因和用量缺失。

本轮无需用户新增服务或配置。用户需核对三件事：参考示例在哪一步进入数据流；未知用量为什么只能报费用下界；失败是实体/聚合/输出口径问题，还是在MODEL阶段根本没拿到SQL。不要把本轮dev68%当作全项目稳定准确率，也不要把证据审计通过写成阶段3通过。
