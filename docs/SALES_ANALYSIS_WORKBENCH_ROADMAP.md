## 1. 执行规则

一次只推进一个阶段。每个阶段都必须按下面顺序执行：

1. 锁定规格编号和验收数字。
2. 先写测试用例。
3. 运行测试确认红灯，并保留失败原因。
4. 写最小实现使测试变绿。
5. 运行阶段测试，再按影响范围运行全量测试。
6. 记录真实数字：准确率、召回率、延迟、Token 或成本；没有数字不算完成。
7. Git 提交，仓库恢复到可运行状态。

付费评测只在候选版本冻结后执行，正常开发测试不能隐式消耗评测 API 预算。

## 3. A-1 分析上下文契约

### 输入

已有 PRD 中的 `sessionId`、`analysisId`、`metric`、`period`、`dimensions`、`filters` 和指标定义 SHA。

### 测试先行

新增 `src/test/java/com/text2sql/agent/analysis/AnalysisContextTest.java`，覆盖：

- 创建上下文保留身份、指标和周期。
- 追加维度不丢失原过滤条件。
- 相同维度不重复。
- 同字段过滤按契约替换或拒绝。
- 输入列表被外部修改后，内部状态不变。
- 空 `sessionId`、`analysisId`、`metric` 被拒绝。
- 指标定义 SHA 被保留。

### 实现

新增 `AnalysisContext`、`AnalysisFilter` 及必要的值对象。使用不可变 record、`List.copyOf` 和 `withDimension` / `withFilter`，暂不接 API、数据库新表或前端。

### 数字验收

- 7 个契约测试全部通过。
- 完整 Maven 单测通过。
- 本阶段新增领域对象单测耗时记录，作为后续基线。
- 生产代码不产生模型调用，API 成本 0。

### 退出条件

所有测试通过、文档映射完整、Git 已提交。

## 4. B-1 销售额下钻

### 输入

A-1 的上下文对象和现有指标、Schema、SQL 校验链路。

### 输出

总销售额、月度趋势、品类排名、地区分布四种结果，所有下钻都继承同一指标、周期和过滤条件。

### 测试范围

先写服务层契约测试，再写 HTTP 验收测试；覆盖上下文继承、维度互斥、空结果、金额单位和只读 SQL。

### 数字验收

- 四种场景各 5 个固定样例，业务结果正确率 ≥ 90%。
- 下钻上下文继承率 100%。
- 查询 P95 ≤ 8 秒。
- 业务响应中 SQL、Token、Prompt 字段出现次数为 0。

### 不做

不做异常检测、复杂报告、流式协议和生产库接入。

## 5. C-1 多轮追问与结果恢复

### 输入

B-1 已成功保存的 `analysisId` 和上下文。

### 输出

最多 3 轮连续分析、短断线恢复、重复请求去重、会话关闭。

### 测试范围

覆盖指代消解、历史压缩不丢指标和过滤、成功/失败终态恢复、相同幂等键零重复模型调用、关闭会话拒绝修改。

### 数字验收

- 连续 3 轮上下文正确率 100%。
- 刷新后成功和失败结果恢复率 100%。
- 幂等重复请求新增模型调用 0 次。

## 6. D-1 业务与诊断隔离

### 输入

C-1 的结果状态和现有执行证据。

### 输出

业务工作台只显示结果、图表、表格、下钻和继续追问；开发诊断入口显示 SQL、Schema、Token、耗时、来源和失败归因。

### 测试范围

DTO 字段白名单测试、权限入口测试、页面文本扫描测试和错误映射测试。

### 数字验收

- 业务页技术字段出现次数为 0。
- 诊断信息完整率 100%。
- 失败归因可定位到检索、生成、校验或执行四层之一。

## 7. E-1 固定评测与回归

### 输入

冻结候选版本和固定评测集，不重新修改题集或门槛。

### 输出

一份包含正确率、召回率、P95、Token、成本和失败归因的报告。

### 数字验收

- 结果正确率沿用项目门槛，目标 ≥ 89%。
- 查询 P95 < 8 秒。
- 每 100 题完整成本 ≤ ¥0.30；模型单价为 0 时明确报告 Token，不伪造费用。
- 不新增未授权评测 API 调用。

## 8. 阶段失败处理

如果阶段测试失败，只修复对应阶段；不通过添加按钮、放宽校验或扩大模型输入来掩盖失败。影响公共提示词、共享口径或公共链路时，修复集中完成后再跑一次完整回归。
