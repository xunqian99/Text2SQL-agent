# 新增冻结留出候选集：首轮评测协议

本协议在新题集第一次真实模型调用前制定。目标是提供一个不再参与本轮调参的新题集及可审计运行路径。它不宣称同作者自验等于第三方独立盲测，也不修改既有 200 题、Gold、提示词、检索或纠错选答逻辑。

## 题集与身份

- 路径 `data/holdout/v1`，100 题，ID 为 `T1-H001` 等，不复用既有 ID；六层配额为 20/20/16/22/10/12，与旧 eval 100 题的层配额一致。
- 新题和 Gold 由当前 AI 作者编写。作者看过旧基准与系统实现，未获得第三方独立口径审核。因此 `independentReview=false`，名称为冻结留出候选集，而非独立盲测。
- 题集仍处于同一 Olist 数据库，覆盖已有字段、表和常见 SQL 算子，不能推导跨库、跨业务域泛化。
- `manifest.json` 绑定文件字节指纹、样本 ID 指纹、配额、参考基准指纹、冻结时间和作者来源。Gold 可执行性自检在冻结之前完成，不能据模型得分更换题目。

## 冻结前检查

1. 新题 Gold 全量 dry-run 100/100，且模型调用为0，检查逐题问题和 Gold SQL 指纹，不只看总分。
2. 使用只读事务对 Gold 自检的最终 SQL 再取行数特征：2题为空集（T2-H016、T4-H012），2题返回仅零值（T1-H017、T1-H019）。全部保留；报告单独分列，弱答案不能冒充同等区分能力。
3. 检查与既有200题及实际加载的 few-shot 的 ID、规范化问题精确重叠。规范化只做 NFKC、空白/标点移除及大小写归一化；它不能证明改写题、模板或 SQL 语义独立。
4. 同时归档 Gold SQL 文本精确重叠与按表数分布。即便精确重叠为0，也不能声称没有模板重复。
5. 冻结后不再更改v1题意、SQL或题量。若真实评测后发现 Gold 缺陷，以 Errata 单独记录，保留原始总分和失败，不覆盖历史证据。

## 运行前门禁与隔离边界

`EvalSuiteGuard` 在 Gold 执行和模型调用之前验证清单。只允许 `split=all`、`limit=0`、无层过滤、`repeat=1`，禁止评测器外层纠错；失败即停止。题库字节、样本ID、题量、分层、参考数据或实际示例重叠不符合清单时均拒绝。

few-shot 仍固定从 `classpath:fewshot/examples.yml` 加载，新题放在资源目录之外；修改评测输入目录不会自动将 Gold 装入 Prompt。生产请求只接收问题和既有 Schema/业务规则。评分在生产返回后执行。

这是运行完整性及工程隔离，**不是访问权限系统**。源码未加密，当前进程和仓库作者可以读取题目；也可以选择不传清单运行普通评测。报告只能说明清单启用且校验通过，不能证明人从未看过题。`declaredIndependentReview` 是来源声明，不是验证过的审核凭证。

## 预注册运行配置与顺序

冻结后提交全部代码、题库和协议，再执行 `scripts/run_holdout_baseline.ps1`：

1. 既有全量 Gold：200题。
2. 新题 Gold：100题，启用冻结门禁。
3. 既有开发集：100题，`split=dev`，一次独立JVM。
4. 新题留出集：100题，`split=all`，一次独立JVM，启用冻结门禁。

真实问答固定开启澄清、生产自纠错（总共最多2次模型调用）及结果检查；关闭缓存、升级路由、工具循环、多轮会话和评测器外层纠错。模型为 `deepseek-flash`，温度0、输出预算8192、Top-8、列剪枝、Join规划、业务指标与2条few-shot保持原配置。成本使用现有配置单价，不能当供应商账单。

每步开始前确认 Git 提交与评测相关源码/题库未变。用户既有演示稿改动和新报告不计为被测源码变动；报告仍诚实记录工作区DIRTY。源码检查不能证明检查间隙未短暂修改又还原，也不能固定厂商内部模型权重。

发布前发现初始本地 YAML 含 CRLF，而仓库声明 LF；`d32218e` 的初始本地字节清单在首次真实模型调用之前被替换。仅将工作文件恢复为该提交已有的 LF 字节，题意和 Gold 均未变；原清单和新旧指纹映射保存在 [格式勘误](../reports/holdout-freeze-20261116/line-ending-errata.json)。原基准本地指纹 `61fd7005…` 对应规范仓库字节 `c3f290e0…`，候选集从 `897853dc…` 对应为 `a7107815…`；历史模型报告不重标指纹或分数。正式脚本在首次调用前另用无过滤 Git 对象哈希比对工作文件与提交字节，避免“Git状态干净但换行不同”的漏洞。

先跑开发集再跑留出集会有时间和缓存预热影响。两个集合难度标签相同不代表真实难度相同，总分差不能直接解释为过拟合幅度。每组只跑一次，不冒充稳定均值或机制消融；之前四配置三轮的模型分数仍绑定原代码。

## 报告及验收标准

- 两个 Gold 自检必须200/200、100/100，否则不开始真实模型评测。
- 保存两个100题真实报告、逐题生产尝试、调用哈希和JSONL账目；未知用量必须单列，不按免费处理。
- 逐层、按表数、失败ID、澄清、实际重试恢复/退化、输入/输出及命中/未命中Token、估算成本和服务调用墙钟P50/P95全部报告，不丢弃低分层或弱答案题。
- 另列“空集/仅零值Gold”4题和其他96题的结果，但主口径始终是完整100题；这些分组仅用于说明答案区分能力。
- 新题预先不设96%门槛。该轮建立候选基线，不是独立盲测通过证明；平均P95<8秒、完整语义契约及后续独立审核仍是未完成要求。
- 一旦查看v1失败，它就被视为诊断/回归集。后续不得一边针对v1失败调规则，一边继续宣称它是未见盲测。第三方审核只能提高Gold可信度，不能消除已经发生的调参污染；若需新的未见测试，应另行征集未用于调优的题集。

复跑示例（产生真实模型费用，新目录防止覆盖）：

```powershell
./scripts/run_holdout_baseline.ps1 -OutputDir reports/holdout-新的日期时间
```

只验证冻结路径而不调模型：

```powershell
./scripts/run_holdout_baseline.ps1 -DryRunOnly -OutputDir reports/holdout-preflight-新的日期时间
```

同一作者无法代替外部独立审核。本轮会提供可审查的题目与Gold，独立审核或外部未见题来源仍需用户协调；该事项不阻塞候选集的工程门禁和首轮数据采集。
