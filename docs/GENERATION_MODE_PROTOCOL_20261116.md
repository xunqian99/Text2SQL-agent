# 显式生成模式：阶段3开发筛选协议

## 问题与单一变量

输出上限2048的前次候选因新增6题截断被否决。此次保留8192上限，只比较省略`reasoning_effort`的供应商默认模式和显式`reasoning_effort=none`。不改变题目、Gold、Prompt、检索、澄清、结果检查、评分器、重试策略或生产默认。

[DeepSeek当前官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)：省略`thinking`与`reasoning_effort`时开启思考，默认强度high；`none`关闭思考；思考模式下温度不生效。此说明支持当前实验的假设，不证明所有历史请求的服务端实际模式，也不保证供应商按配置执行。因此报告字段命名为`configuredReasoningEffort`，不叫实际模式。原始推理文本不记录。

## 题目、次数与冻结

- 原始基准200道，固定dev100/eval100；另有候选100道，本轮不用，不新建题库。
- Gold全200题自检200/200、模型调用0，失败则停止。
- 同100道dev题，各模式跑一次：100道不同题、2配置、1轮、累计200次真实请求。
- 顺序Gold → provider-default → reasoning-none，每组独立JVM。先提交实现、协议、运行及审计脚本；每步前后校验提交与保护文件原始SHA-256，含私有配置哈希但不存密钥。禁止覆盖历史输出目录。
- 这是开发筛选。默认模式先跑存在供应商缓存预热和时间漂移影响；候选有利才冻结另一份交替三轮确认协议。单轮不证明因果或盲测，不进入阶段4。

## 固定条件与取证

模型deepseek-flash、温度0、输出8192、请求15秒、最多2次模型调用、重试准入剩余2秒、SDK最多1次。Top8、列剪枝、Join规划、语义指标、2条few-shot固定；澄清、生产纠错、结果检查开启；缓存、路由、工具循环、会话、评测器外层纠错关闭。价格仍为每千Token：未命中输入0.001元、命中输入0.00002元、输出0.004元，仅为配置估价。

`agent.llm.reasoning-effort`默认`provider-default`，不发送同名供应商值；显式支持none/low/high/max，其他值启动绑定失败，不静默降级。供应商不支持时按真实调用失败记录，不偷偷换回默认。全局Key和BYOK共用四入口optionsBuilder，不在自动工具循环中藏调用。

本地HTTP捕获验证实际请求字段：两种模式×四入口×全局/BYOK共16个组合；另检查low/high/max透传、默认/空值归一化与3种非法值，共23条新增Java测试。不得以仅检查builder对象代替线上格式序列化证据。没有新增依赖，使用已有Spring AI1.1.8的reasoningEffort接口与JDK HttpServer。

评测effectiveConfig和JSONL记录`configuredReasoningEffort`；请求ID/调用编号关联账目，Prompt哈希保持仅标识输入消息，不能把模式配置藏进或混同Prompt哈希。两个模式首答消息哈希、题意/Gold/结果指纹应一致；usage未知保留未知，晚到记录单列，不当0元。返回停止原因与半条SQL拒绝机制不变。

## 预先固定的判定

完整100题分母，澄清/超时/失败保留。P95是每组墙钟第95顺位值，包含重试；同时记录P50/平均/最大、正确数、SQL成功数、失败、重试/恢复、输入缓存明细、Token、已知费用下界和未知调用。

候选进入三轮确认须同时满足：正确数下降≤2/100；P95较同期默认组下降≥10%；新增截断请求≤1/100；完整100题费用≤0.30元且未知usage为0；最多2次调用、墙钟≤16秒工程界限、取消提交拒绝0；证据审计通过。绝对P95是否<8秒另列，不能用相对降幅替代阶段门槛。任一不满足不推广；完整费用未知则该项未确认。

正式验收仍需三轮eval平均P95<8秒、相对冻结基线平均准确率下降≤2个百分点及完整费用门槛。关闭思考可能损害复杂SQL语义，即使很快也不能跳过准确率门禁。本轮不调截断重试，以免同时改变第二个因素。

## 技术导读与可验收路径

例如“订单总数”：问题→原检索/Prompt→统一optionsBuilder选择省略或none→Spring AI序列化→HTTP调用→原SQL提取/只读护栏/执行→账目与结果。模式控制只作用于生成参数，不重排召回结果或修改SQL答案。日志的configured标记证明客户端意图，本地捕获证明字段发出，供应商实际执行仍是外部边界。

验收顺序：Java全量测试→run_eval的两种Preview→提交冻结→运行脚本→审计报告与原字节清单→按上面门槛决定是否确认。模型准确率/延迟/费用只在真实实验后填写，23项本地测试不冒充准确率提升。

替代方案：在Prompt中要求“不要思考”无法可靠控制协议模式；直接把所有请求默认改none会改变现网行为、混淆基线，因此采用显式可选参数，先筛选后推广。

面试追问：“温度0为何还波动？”回答应区分供应商忽略参数、后端非确定性与输入变化，配置快照和Prompt指纹分开核对。“关闭思考是否一定省钱？”回答应看完整请求含重试的Token与准确率，usage缺失只能报下界，不能按回复长度推算费用。

本项不需要用户新增服务或凭据；已有本地环境直接运行。用户需能核对数据流、每次调用费用和错误层级，而非只记一个总分。

冻结前本地验证已执行：Java全量459/459、失败/错误/跳过均0（新增23项）；离线审计46/46（新增6项使用明确标注的合成协议夹具，不是真实模型记录）；两种Preview输出均固定8192，仅模式参数不同。日志为`reports/generation-mode-full-tests.log`与`reports/generation-mode-audit-tests.log`。影响范围是生成参数、评测快照、JSONL新增字段；SQL/检索/重试/Gold不变，数据库日志表未迁移，模式标记只在JSONL与评测配置中。
