主比较基线提前选择已归档的`reports/generation-mode-matrix-20261116`中r1-default、r2-default、r3-default：91/90/92，平均91.00%，测量提交1e3a11f。选择它是因为它已启用与当前相同的15秒/2调用预算、生产纠错和结果检查，且是最近已冻结的完整三轮默认模式；不采用被否决的none组，也不在看到本轮结果后改选较低基线。

阶段2回归门槛：三轮原eval100平均准确率至少89.00%，即相对91.00%退步不超过2pp。原改进方案完整检查组90.33%同时列出作为历史参考，其对应88.33%下限更宽，不替代本轮提前选定的89.00%。所有失败、澄清、超时留在100题分母中，不重跑择优，不改题目、Gold、评分器。

这是历史比较，不是同期单因素对照。期间包含会员定义、NULL、明确复购分母澄清、真人身份以及p10单位/形状等修复；不能将总分差因果归于p10，也不能推断跨库泛化。原基线与本轮逐题题目、Gold SQL、Gold结果指纹须一致；配置增加观测/门禁字段可以记录，但原基线已有的有效参数除Prompt版本外必须一致。原始Gold执行时间不同不参与语义比较。

本轮目标失败固定为原20条中的T4-001（身份）、T3-002（形状）、T6-003（单位）。旧超时T5-002归阶段3暂缓。至少一半目标严格修复即至少2/3；以已冻结客户4条和输出6条各一次的专项证据判定，不从三轮中择优挑答。T4-001身份机制已修但专项仍因未规定Top10并列名单严格失败，保留失败；另外两条原题原Gold专项已匹配，因此当前目标为2/3，不声称3/3。

## 输入、顺序和运行

题库仍data/eval原200题。仅原eval分片100题，顺序r1、r2、r3，每轮一次；共300个请求，不新增题目。先Gold全200题dry-run一次，模型0调用，必须200/200。任意轮运行失败保留现场并停止，不隐式重放。需要后续处理时先记录异常，不删目录。

固定deepseek-flash、temperature0、maxTokens8192、provider-default思考模式、显式四步提示开启、p10-result-contract-v10；检索TopK8、列剪枝、join hints/plan、semantic、fewshot2、澄清、生产纠错最多2次和结果检查开启；eval侧纠错关闭；cache/routing/tool/conversation关闭。请求预算15000ms、最多2模型调用、重试最少剩余2000ms，SDK单次尝试。参数来自现有run_eval.ps1的Preview，正式由相同已编译Java类启动，冻结classes/test-classes/依赖JAR的SHA。

启动前冻结当前Git提交、保护源码/测试/题库/脚本/基线/专项/协议字节、私有配置SHA和实际运行文件SHA。每轮前后复核，保护源改动则停止。每条模型调用沿用生成入口及实际发送的DeepSeek空闲门禁，保留120秒边界余量，不关闭门禁。Key仅环境继承，不输出值。
