## 技术与设计导读

### 1. 具体请求与数据流

输入“支付方式里信用卡和boleto各占多少笔？”→原Hybrid检索/指标依赖/列剪枝完成→ValueRetriever继续输出原有取值提示→CountComparisonContract检查本次真实可用表列，并从已有词典枚举中识别信用卡→order_payments.payment_type=credit_card、boleto→同字段物理值boleto→按原文出现位置形成两条Binding→在valueHints末尾追加独立标记REQUEST_RESULT_CONTRACT named_filter_counts_v1，明确“一行、两计数列、按此顺序”与两个条件计数表达式→原PromptTemplate将其和Schema、指标、示例、原问题组装→模型生成→既有AST/EXPLAIN/只读执行。

若用户补充“请用纵表”，决策为EXPLICIT_OR_GROUP_LAYOUT，不追加默认契约；原显式问题照常送入。原值提示方法findMatches/renderValueHints(List)没有修改取值规则，新重载只在可判定时追加契约；Full、Hybrid正常和全量回退路径使用同一方法。各路径实际可用字段不同，可能合理地得到不同的歧义/弃权结果，不能声称任意路径一定都激活。

### 2. 来源凭据与确定性条件

核心Java类CountComparisonContract：decision记录MATCHED或弃权原因；bindings保留每个值的matchedWord、table、column、value、source、start、end。source区分GLOSSARY_LABEL与PHYSICAL_VALUE；物理值也来自词典声明，非模型推测。start/end是原始字符串的Java UTF-16下标、左闭右开，保留原文大小写，未去空白重写。别名重复但表列值相同按同一身份去重，最先出现的完整匹配确定列顺序；同起点优先较长匹配。

激活条件：存在记录计数措辞与枚举连接词；没有显式形状/分组、“按…”维度指令（保留“按此顺序/按顺序”计数列排序表达），没有支持列表内的比例、金额、平均、否定、差值或时间组合；真实保留字段中恰好一个字段有2–8个不同枚举值。英文物理值须为字母开头且至少3字符的标识词，并检查ASCII词边界，避免superboleto误命中boleto；不直接拿1、2或年份当枚举值。四位数字与常见周期词保守视为时间/复杂组合，不在这里解释。

本层不接收directHits/expandedTables来源标签，不能声称自己知道每个字段是直接命中还是扩展加入；它只使用最终可用字段和词典枚举身份。上游的检索来源标记、分数、0.4关系衰减与桥接表上限仍保留不变。出现多个候选字段时，本层不靠检索分数猜选一个，记录全部候选后弃权。

### 3. 数学、边界与量化证据

没有新打分、权重或Top-K：列顺序来自原文位置，不来自字典长度或检索分数。超过8个值整项弃权并保留全部证据，不截取前8个隐藏其他条件；不同值匹配区间重叠也弃权。只有一个值或字段被剪掉就不注入，不能用缺失字段创建不可执行表达式。

每列是独立COUNT(*) FILTER，允许子集交叠、NULL谓词不计入、无记录计0；限定符要求按实际SQL别名改写，字符串值转义单引号。词典声明不证明数据库当前一定有该物理值，无记录可以合法得到0。共享过滤与事实粒度仍由原问题决定，不自动加Join、不改用户原文、不转置响应、不从Gold给纠错反馈。

Java831/831、77套件、0失败/错误/跳过，新增24项机制与三路径/边界测试；首次829/829后补充“按承运商”和省略年字的四位年份保护，首轮通过日志也保留。原200题只有T2-013/T2-014追加请求契约，其余198题完整Prompt与p12相同；全部200题检索表/顺序/分数/扩展来源/列/指标/示例/Join和旧枚举提示不变。系统提示字节200/200不变，版本变化仍会改变全局配置观测和语义缓存身份，不能说只有两条缓存键变化。

这24项测试不是模型准确率；机制只确定注入什么，不保证模型一定遵守。有限语言规则会漏掉其他措辞、部分复杂否定或组合；对未匹配情况保留原链路，不宣称通用意图解析器或任意SQL等价证明器。保守拒绝“未/非”等词也可能放弃合法枚举请求，这是以覆盖率换取不误覆盖的代价。

### 4. 取舍与面试追问

没继续给全局提示添加“信用卡必须横表”的补丁，也没写订单/支付专属题ID分支；这些会把失败样本编码进规则而无法解释泛化。复用经过Schema校验的枚举元数据，并明确有限的适用条件，新增业务表只需已有词典枚举与真实列即可参与。

问“为什么不用再调用模型判断形状？”——为已有确定元数据的有限场景多加一次生成调用会增加费用、延迟和另一层不确定性；有歧义则弃权，不用模型猜测粉饰确定性。问“为什么不强行把两行转成两列？”——响应后转置可能掩盖筛选、顺序和缺失值错误；本层在生成前声明契约，原评分保留失败，生成后不改结果。
