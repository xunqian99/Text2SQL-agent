# Olist V3正式参考修订（2026-11-19）

这是原正式100题的一对一参考修订，不是新盲测，也不是模型成绩。三个原题独立审查者完成100题复核后，主agent另写V3候选，再由未编写该候选或参与生产调参的新上下文审查者逐题检查。最终参考一致性复核100 PASS、0 DEFECT、0 AMBIGUOUS，供应商API调用0。

## 1. 修订范围与实测

100题全部保留原题号及来源，不增删难题；42题明确题面、45题修改SQL，包含统计粒度/事实覆盖/完整身份、时间口径、并列裁决、零分母和NULL边界。旧v2、评分器及旧78%成绩均不覆盖；原89%门槛没有降低。

候选首次复核79 PASS、13 DEFECT、8 AMBIGUOUS。主agent集中修订后99/0/1，最后只补验T5-016，最终100/0/0。首次全100 Gold实际执行成功808行，集中复验13条SQL的双向EXCEPT ALL均0，最后T5-016实际20行且相对上一稿双向差异0；合并后仍808行，最大单题52行。没有把执行成功冒充语义正确，也没有为小修反复跑全100或调用付费模型。

## 2. 具体请求的数据流

“优惠券带来的GMV、优惠金额和折扣率”：coupon_usages先按order_id合计优惠，order_items另按order_id合计商品额加运费，两张一行一订单的集合再与有效订单关联。GMV1930583.35、优惠417833.13、折扣21.64%；原参考将优惠连接到多条商品明细，放大到473711.60、24.54%。券事实身份与商品事实身份分别保留，不能SUM(DISTINCT金额)误删同额真实记录。

“最新快照等级”：按member_id分区，用snapshot_date降序、同日snapshot_id降序确定一条；snapshot_id才是实际主键，不是假造(member_id,date)唯一性。日期未知不参与最新判断，当前/快照等级不可匹配字典时不声称已确认不一致。该规则在新版题面显式说明，不倒改用户历史问题。

“最近N天”沿已确认自然日契约；仅实际有事实月份、完整月份缺失NULL、明确计数缺失0等范围在题面分别固定。名称/ID、记录/自然人、按金额/笔数排名不再隐式混用。TopN先比较最终展示指标，再按完整身份裁决，主指标优先，不用身份加权挤掉高值。

## 3. 版本与评价边界

最终文件位于`data/benchmarks/olist-v3-candidate`，独立接受报告固定6份YAML、当前p21契约及DDL指纹；名称中的candidate不表示已获得模型验收。原各轮审查、曾失败的稿件和修订链均保留。

41条参考SQL未写LIMIT，用于定义完整预期结果，而不是模型生成源形式。保留它们避免改变原评分器对ORDER BY+LIMIT的处理；生产生成规则与执行器行数上限没有豁免。当前最大52行低于执行器上限，不证明未来任意数据规模不会截断。

新版本必须在同一V3上测历史基线安全回补版与p21候选；不能用V3分数减旧v2的78%声称模型涨分。正式三轮仍要求均值至少89%，且相对同版本基线退步不超过2pp。开发筛选的参考也需要先独立审核，才有自洽的晋级判断；此处没有宣布整个评测协议已冻结或提前启动模型。

独立审查初读T1—T3时接触候选notes，报告如实披露，后续不以作者notes作证；共享文件系统也不提供操作系统隔离。后续修订是审查反馈后复核，不是最终版完全盲审。全部题本来已被用于调参，不能再叫未见测试。

## 4. 设计权衡与答辩

不用“SQL都能跑”作为Gold通过条件，因为零分母、孤儿维度、稀疏月份与NULL金额榜单可能在当前快照恰好不出错；需要只读反例验证。也不直接覆盖旧Gold，否则无法区分参考修订和模型变化。

面试问“参考改了是不是作弊”：回答来源一对一、旧失败保留、审查独立、同版本双基线对照；修订分差单列不归因系统收益。问“100 PASS是否100%准确率”：回答它仅代表参考语义复核无剩余问题，模型API调用为0，真实准确率必须另测。

无需用户操作。本批需掌握数据事实如何分别聚合、费用新增为0、错误先落在参考/契约层。原阶段2、整体未验收，阶段3继续暂缓。
