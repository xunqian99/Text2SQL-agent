# low思考强度：阶段3开发筛选协议

全局none的三轮确认已被否决：平均准确率87.33% vs 同期91.00%，虽然P95只有1.474秒。此次只检验显式`reasoning_effort=low`能否保留思考并缩短拖尾，不同时改变输出上限、Prompt、检索、澄清、纠错、题意、Gold或评分。生产默认仍省略参数。

[DeepSeek接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)中low属于开启思考的强度配置，none关闭思考，默认强度high。文档支持配置语义，不证明服务端内部实际采取了某个推理过程或保证low一定更快。因此字段继续叫configuredReasoningEffort，不记录原始推理文本，不把completion Token全叫最终SQL Token。

## 固定输入与运行顺序

使用原始200题做Gold自检，须200/200、模型调用0；然后同一批dev100题按provider-default → reasoning-low各运行一轮，各独立JVM。共100道不同题、2模式、200次真实请求，不新增题目，额外候选100题不参与。不能拿历史dev65%或旧eval91%替代本轮同期基线。

复用`run_generation_mode_screen.ps1 -CandidateReasoningEffort low`和原逐请求审计。新清单类型low-reasoning-screen-v1明确候选low；旧generation-mode-screen-v1仍只对应none，旧归档不重标、不覆写。清单中的模式、评测effectiveConfig和每个可用JSONL条目的模式必须对齐，消息Prompt哈希独立比较。

协议和脚本提交后运行，输出目录不得覆盖；每步前后检查同一Git提交、保护路径状态和原字节SHA-256。保护源码、pom、data/eval、运行/审计及依赖、当前协议和私有配置哈希，不归档私有配置内容。只有配置档位变化，不引入新依赖或Java业务代码。

固定模型deepseek-flash，温度0，输出8192，总预算15秒/最多2调用/重试准入剩余2秒、SDK1次；Top8、列剪枝、Join规划、语义指标、2条few-shot、澄清、生产纠错和结果检查开启；应用缓存、路由、工具循环、会话及评测器外层纠错关闭。价格仍为每千Token输入未命中0.001元、命中0.00002元、输出0.004元，仅是配置估价。

## 事先判定与边界

low进入正式三轮确认须同时满足：

1. 正确数相对同期默认下降≤2/100，所有100题均在分母，包括澄清、超时和拒绝。
2. 请求墙钟P95较同期下降≥10%；绝对P95是否<8秒单列，不能用相对降幅替代正式门槛。
3. 新增截断请求≤1/100；截断由服务端finish_reason=length判定，不凭Token数猜测。
4. 完整配置估价≤¥0.30/100题且low未知usage为0；未知不是免费，晚到用量单列，缺失则不确认完整费用。
5. 每请求模型调用≤2、墙钟≤16秒工程界限、取消提交拒绝0；输入/Gold/首答Prompt/配置/选答/账目审计通过。

报告T1至T6及关联表数分层、全部失败、逐题对错转换、重试/恢复/退化、缓存命中与未命中、已知Token、未知调用和费用。特别记录深层题退步，不能只展示总分。供应商缓存和先默认后low的时间顺序会影响结果，单轮只能筛选；有利才单独冻结交替三轮eval确认，正式准确率仍需≥90%且相对同期下降≤2pp，不在低分上重设基线。

## 技术与设计导读、验收路径

例如“按英文类目统计退款前15”：原有检索和Prompt→统一optionsBuilder发送low→供应商回复SQL→原AST/字段/成本/只读执行→类目和退款金额结果表。requestId+callNumber追踪每次调用，configuredReasoningEffort追踪客户端模式意图，Prompt哈希只标识输入。金额是否按明细聚合仍由生成语义决定，low不等于语义证明，也不改变表列打分或来源标记。

已有Java459/459中的实际HTTP测试已覆盖low透传；此次Java源码不变，不宣称重新执行全量Java。脚本扩展须通过新增low协议审计用例、历史none归档只读审计与参数Preview，然后提交冻结，执行Gold与两组真实请求，核对原始证据并归档数字。若失败就保留失败证据并拒绝候选，阶段3仍未过，不进入阶段4。

替代方案是全局none，已因复杂语义退步被正式否决；本次low用保留思考换取可能的质量，不预先保证收益。面试追问：“low仍超时怎么办？”答：共享15秒/2调用预算保底返回并记未知费用，不能把请求上限提高掩盖P95。“为什么不同时修退款规则？”答：那会混入第二个主要变量，使模式收益无法归因；语义契约问题另行记录。

无需用户重配服务或环境变量；要核对具体请求的数据流、完整调用费用和错在字段/Join/口径哪层，不能只背一个准确率。
