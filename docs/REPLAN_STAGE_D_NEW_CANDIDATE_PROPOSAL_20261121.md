例如问题“2018 年每个月的 GMV 中，新客和老客各贡献多少？”：检索先生成带来源的 `SchemaContext`；指标匹配命中 `customer_cohort` 与 `gmv_with_freight`，依赖表仍从原集合保留；N1 只把两条定义共同重复的有效订单说明提取到共享段，单独保留自然人身份、历史首单、GMV 含运费、分母、缺失周期和 NULL 规则；`PromptTemplate` 再拼接 DDL、画像、示例和原问题。生成后的 SQL 仍经过原 AST/授权校验和只读执行，N1 不改 SQL，也不能把本地 Gold 自检当成模型答对。

## 技术与设计导读

1. **怎么实现**：请求进入检索层后保留四类来源标记，指标层给出 `MATCHED/REQUIRED_CONTEXT_MISSING/EXCLUDED_CONTEXT` 证据；渲染层只对完全相同的约束文本做共享，不确定即回退完整规则，最终仍走原生成、校验、执行和账务链。
2. **用什么实现**：`HybridSchemaProvider`、`MetricRegistry`、`SchemaContext` 和 `PromptTemplate`；检索排序仍是 direct 优先、扩展衰减 0.4、Top-K 8、桥接 2 表。共享段只是字符串渲染，不是新打分器或新路由。
3. **效果怎么量化**：免费准入目标是字符总量减少≥20%、字符 P95 不增、C1 晚到题平均字符再降≥10%，新增危险放行 0；付费阶段才测真实 Token、准确率、P95、超时和完整费用。字符减少不能冒充 Token 或供应商账单下降。
4. **为什么这样做**：选择共享重复约束，是因为它比按关键词删除规则更容易证明边界；后者在复合、否定、同名和业务依赖缺失时会把必要定义删掉。面试追问一：为什么不直接删长指标定义？回答是分母、身份、NULL 和例外是业务契约，删掉会把可执行错误变成静默口径错误。面试追问二：扩展表为什么不会挤掉直接命中？回答是扩展分数最多按边权乘 0.4 衰减，排序同分 direct 二级保送；但 metricDependencies/safetyBridges 是另一路，不能冒充 lexical direct/expanded 证据。
5. **需要用户配合**：只有在免费 N1 通过后，你需要确认累计限额和题数；当前不需要提供 Key 或启动外部服务。任何实际请求仍必须在发送前核对官方空闲时段。
