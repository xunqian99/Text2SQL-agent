# 澄清、自纠错、结果检查：真实模型对照协议

本协议在本轮真实调用前冻结。目标是区分模型自身波动与生产重试收益，不修改评测题目、Gold SQL、结果比较器、提示词、检索参数或模型参数。它不代表实验已经完成。

## 实验矩阵

沿用现有 eval 100 题，每组启动三个独立 JVM；不用缓存重复负载代替独立重复。

| 组 | 澄清 | 自纠错 | 结果检查 | 每请求模型调用上限 |
|---|---|---|---|---:|
| baseline | 开 | 关 | 关 | 1 |
| correction | 开 | 开 | 关 | 2 |
| checker | 开 | 开 | 开 | 2 |
| no-clarification | 关 | 关 | 关 | 1 |

固定 local、deepseek-flash、temperature=0、输出预算 8192、Top-8、列剪枝、Join 规划、指标语义及两条示例。缓存、升级路由、工具循环、多轮会话、评测器外层纠错均关闭。沿用本地配置估算价格，不宣称为实时供应商价格或实际扣款。

每轮将运行顺序左移一位：第一轮 baseline/correction/checker/no-clarification，第二轮 correction/checker/no-clarification/baseline，第三轮 checker/no-clarification/baseline/correction。该顺序降低全部基线总在最早时段的偏差，但三轮并非完整平衡设计，不能消除服务负载或厂商缓存的时间影响。题目顺序保持不变。

## 证据与归因

`EvaluationTrace` 仅在评测器以 try-with-resources 开启的同步调用范围内收集事实。线程隔离，不继承到子线程；关闭后移除线程上下文。普通 HTTP 请求不开启该范围，不留存额外结果。异步链路不能直接沿用这个上下文传播假设。

生产链路记录每次模型的有序消息 SHA-256、用量和状态，以及各次 SQL 校验/执行响应、重试触发原因和最终选答序号。列来源规则仍由上一阶段的 `ResultColumnPolicy` 负责，本阶段不改变它的分类或优先级。

身份追踪分成两层：`calls[].number` 标识实际模型调用，`productionAttempts[].number` 标识生成失败或 SQL 执行尝试；固定矩阵关闭其他调用路径后，两者应一一对应。`selectedAttempt` 明确指出采用第几次，不能从“SQL 字符串恰好相同”猜测选答。请求总账包含未采用的调用，不重复累计已合并的响应账目。

Gold 在评测器已有的参考执行中产生；生产 ask 返回、记录范围关闭后，`EvaluationEvidence` 才独立比较每次答案。Gold 不传入记录器、编排器或纠错反馈。保存问题/Gold SQL/Gold 结果指纹、每次正确性、SQL、列名、结果行数及结果指纹，不额外保存结果数据行或完整提示词正文。

网络失败未返回 usage 时，调用保留指纹且用量为 null。它表示未知，不是 0 费用；汇总器拒绝为这种运行认证完整账目。模型 SDK 内部传输重试不等于一次新的编排尝试；这里的调用数统计应用层 `ChatModel.call`，不证明供应商实际请求数或扣款数。

跨组分数变化只报告为观察。真正的重试收益使用同一请求内的首答与最终答案：错→对为修复，对→错为退化；第二次执行成功却仍与 Gold 不符不算修复。澄清仍占总分母，不作为已答对，不因“需要澄清”而剔除样本。

## 验收门禁

1. 全量测试通过；200 条 Gold dry-run 仍为 200/200。
2. 四组各三轮、每轮 100 条，报告元信息除实验开关和时间/工作区标记外相同。记录实际提交；源码在矩阵中变化即停止，不混合结果。
3. 相同题目的首答 prompt 指纹一致；问题、Gold SQL 和 Gold 返回结果指纹相同。工作区 DIRTY 的非实验来源须说明。
4. 保存逐题生产尝试与选答；调用次数不超预算；请求总账、逐调用记录、JSONL 原始账目、报告汇总一致。
5. 给出每轮分数、均值/范围/样本标准差、分层结果、失败并集、输入/输出 token、命中/未命中 token、成本、P50/P95、修复与退化。
6. 如 P95 不低于 8 秒，明确记录未达标及拖尾题，不降低门槛。不得以检查器微秒级耗时代替端到端延迟。

`passedEvidenceAudit` 仅表示实验记录通过一致性审计，不表示产品性能达标、机制有显著收益或盲测通过。现有 eval 已用于诊断，不是未见盲测；改进方案中的独立盲测仍是后续未完成项。

## 复跑

```powershell
mvn test
./scripts/run_eval.ps1 -DryRun -Split all -OutputDir target/ablation-preflight
./scripts/run_ablation.ps1
python scripts/summarize_ablation.py reports/ablation-实际时间
```

矩阵会产生真实模型费用；Key 继续从环境变量读取。每次生成新目录，禁止覆盖已有实验，运行日志、原始账目和报告分别保存在每轮目录。矩阵中断后先检查原进程和 manifest，不能因等待超时就重启付费实验。

技术取舍：选择受限范围的内存事实记录，而非打开所有 prompt/response 正文日志，避免靠时间戳猜测题目与调用的对应关系。它适用于当前同步单轮实验；不声称已经提供跨服务链路追踪。面试时应能解释“答案选择与费用累计为何独立”以及“多轮均分为何仍不能直接证明因果”。
