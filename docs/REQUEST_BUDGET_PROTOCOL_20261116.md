# 请求总预算：预注册三轮对照协议

本协议在新预算实现的首次真实供应商评测前冻结。工程机制和436/436 Java测试见[设计导读](REQUEST_BUDGET_DESIGN_20261116.md)。本轮只比较同一新代码下请求预算off/on，不修改题目、Gold、Prompt、澄清、检索与语义规则，不证明独立盲测。

## 输入与运行顺序

固定既有`data/eval`全量200题先做Gold自检，必须200/200且模型调用0。真实比较用原有`split=eval`固定100题（ID的Java hashCode分组），每组3次独立JVM，分母始终100，超时、澄清、生成失败均保留。旧eval已用于调优，只能称内部回归评测。

代码、输入和本协议先提交，再运行`scripts/run_request_budget_matrix.ps1`。脚本拒绝覆盖输出目录，每轮确认相同Git提交、保护路径状态和原始文件SHA-256；输入YAML还与提交原字节比对。用户演示稿修改及并行内部审核文档不属于被测生产路径，工作区整体可为DIRTY，必须如实记录。

顺序固定为：Gold → r1-off → r1-on → r2-on → r2-off → r3-off → r3-on。交替顺序减轻时间漂移影响，不能消除供应商缓存和负载差异；3轮不是大样本置信保证，不宣称模型内部权重已冻结。中途失败保留原目录和失败状态，不挑高分替换；如需重跑整组需另建目录并解释原因。

## 唯一主要变量

- on：15000ms总预算、最多2次模型调用、纠错准入剩余至少2000ms。
- off：只关闭请求预算，其余参数与on相同；保留HTTP60秒、数据库10秒单次后备超时。
- 两边均为新JDK HTTP传输，Spring AI SDK `maxAttempts=1`，不是旧SDK默认重试代码。不能用历史报告替代同期off。
- 固定`deepseek-flash`、温度0、输出8192Token、Top-8、列剪枝、Join规划、业务指标、2条few-shot；开启澄清、生产自纠错（总共最多2次生成尝试）、结果检查；关闭应用缓存、升级路由、工具循环、会话和评测器外层纠错。
- 费用沿用配置估算：未命中输入/命中输入/输出分别¥0.001/0.00002/0.004每千Token，不等于当前公开价核验或供应商账单。报告记录真实配置；若本地费用配置与冻结预期不一致则审计失败。

## 不得事后改变的门槛与口径

1. on三轮墙钟P95的算术平均 **<8000ms**。单轮100题取排序第95个值，另列每轮和拖尾题；15秒预算不是8秒P95目标。
2. on三轮平均准确率相对同期off下降 **不超过2个百分点**。每轮正确数/100；超时计失败，但已成功首答回退仍按最终结果与Gold比较，并另列截止终止数量。
3. on每轮100题估算费用 **≤¥0.30**。所有已发起调用均计数，未采用纠错也计费。未知usage时只能给已知下界，完整费用门槛标为无法确认；晚到JSONL单列对账，不能偷偷改原评分或把未知当免费。
4. on调用数不得超过2。截止超时项逐题报告实际墙钟和超过15000ms的偏差，不用P95吞掉少数超时；非硬实时调度，允许工程验证偏差1000ms，超过则单列异常并阻断有界返回验收。另报`cancellationRejected`，出现非0则资源清理验收不通过；0不证明所有驱动清理已完成。

## 证据审计

保存manifest、各轮JSON报告、JSONL逐调用记录及本地运行日志。对齐固定样本ID、题目/Gold SQL/Gold结果哈希、配置白名单、首答Prompt哈希；检查调用/尝试编号、`IN_FLIGHT`、`REQUEST_STOP`、最终选答与最终SQL/状态/评分一致。超时首答回退时采用原首答，停止尝试不能冒充额外模型调用。

账目分别核对：请求已知总账、逐调用已知Token和费用、未知调用、`requestId + callNumber`关联的晚到记录。late记录不得重复加入已知账目；未知不能让证据审计自动忽略，而是单列并使完整成本门槛无法确认。对照提示词哈希有差异时报告具体ID，不宣称只改变预算；跨轮本身也需要核对。

原`summarize_holdout.py`的“每次尝试等于每次调用”假设不适合预算停止证据；本轮使用单独离线审计。报告按全量分母给出准确率、分层、调用数、输入/输出与缓存Token、P50/P95、最大墙钟、重试恢复/退化、停止阶段、首答回退与最慢题。

题集内部交叉审核可以并行，不能在本轮中据其意见修订任何输入。AI内部复核不等于第三方独立盲测；若发现确定Gold缺陷，保留原始主分数并单列勘误，重新评测必须使用新协议。
