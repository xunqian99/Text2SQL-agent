# 新上下文子agent契约复核协议（2026-11-19）

用户补充目标：“未参与出题和调参的人可以使用子agent来完成”。该授权解除此前“必须等待人工独立复核”的实施限制；保留既有报告对其当时证据的描述，不倒填人工签字。本次仍是AI复核，不冒充人类业务专家、外部机构认证或未见盲测实测。

## 1. 复核对象与隔离

复核原正式eval100，而非只审核已标出的失败题。三个新上下文agent均使用`fork_turns=none`，未继承主agent历史讨论和先前审计结论，未参与该批原题/Gold编写及生产调参；职责只限审查，不修改生产、Prompt、原题、Gold、评分或门槛。

| 复核agent | 范围 | 题数 | 输入文件 |
|---|---|---:|---|
| `/root/review_basic_time` | T1/T2/T3 | 56 | `basic_time-input.json` |
| `/root/review_joins` | T4 | 22 | `joins-input.json` |
| `/root/review_deep_business` | T5/T6 | 22 | `deep_business-input.json` |

输入只含原题号、难度、问题和Gold SQL；不附主agent之前判出的冲突清单、条件上限或模型失分。审查者只能读取当前产品规则源码、指标/枚举/歧义配置、实际数据库Schema；明确禁止读取历史模型输出、其他审计结论和原复核包中的AI提示。

这属于流程隔离，所有agent仍共享文件系统；`fork_turns=none`证明未传递对话历史，不能证明操作系统禁止其他文件读取。报告须如实声明访问范围与来源，不将自述当访问控制保证。

## 2. 独立审查规则

每题分别判断：统计对象/完整身份、JOIN基数、各指标事实全集、金额与计数去重、时间参照及开闭、名称/ID投影、单位/精度、NULL/零事实和并列排序。产品默认与Gold不同不等于Gold存在算术错误，现库恰好同值不等于一般语义等价。

每题一个主结论：`KEEP`、`CONTRACT_CONFLICT`、`REFERENCE_DEFECT`、`AMBIGUOUS`或`COINCIDENTAL_EQUIVALENCE`；其他问题另记。确定问题需有可追溯的业务契约、SQL反例或真实只读查询结果。不要求复现主agent结论，也不能为达到某个数量把可疑点强判错误。

数据库只允许`text2sql_ro`账号、`BEGIN READ ONLY`、8秒语句超时。不得调用DeepSeek或其他供应商模型API，API调用/Token/费用均单列为0；这里的子agent推理不计作被测Text2SQL系统的模型评测。

## 3. 汇总与后续限制

三份报告写入`reports/independent-contract-review-20261119`，每题保留理由、来源、核查SQL及结果、建议裁决。主agent在各份独立完成后再比较先前审计；不回传原结论诱导尚未完成的审查。分歧保留原文和反证，不能以多数票替代事实证明。

原v2题库、Gold、评分器、89%门槛和全部历史成绩保持。若独立复核支持参考修订，另建明确版本和差异表；必须先冻结新协议与同版本基线，再统一运行。参考修订造成的分差不能算模型收益，也不能把另一个更容易通过的题库替代原阶段目标。

这100题已被主agent用于调参，因此复核完成不会将原题重新变成盲测。独立未见题的作者、复核者、候选代码冻结时间与首次暴露时间仍须另行记录，不能用这次审查代替阶段1盲测。阶段3加速继续遵循此前暂缓决定。
