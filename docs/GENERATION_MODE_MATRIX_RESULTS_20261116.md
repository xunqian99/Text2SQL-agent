## 技术与设计导读

以“用英文类目名统计退款金额，取前15”为例：问题→原检索/Join提示/业务上下文→统一optionsBuilder选择省略或显式none→Spring AI HTTP调用→原SQL提取→AST/字段/EXPLAIN/只读执行→结构化结果与Gold比较。none仍可输出一条能执行的SQL，但如果把退款总额放到明细粒度累加，输出的前15类目及金额就可能错误，现有结果检查不具备通用业务等价证明能力。

实现抓手为`AgentProperties.Llm.reasoningEffort`、`LlmSqlGenerator.optionsBuilder`、`EvalRunner.effectiveConfig`、`LlmCallLog`模式字段及矩阵运行/审计脚本。四入口、全局/BYOK共用参数路径；默认provider-default是内部审计标记，不会发送给供应商。非法配置提前拒绝，不支持参数的供应商调用失败时不偷偷改回默认。Prompt身份、模式身份、请求/调用身份分开；没有调整表列打分或Top-K权重。

Java459/459（含新增23项模式测试和16个真实本地HTTP组合），离线审计57/57（矩阵新增11项）；Java业务源码相对ed52a67未变，正式运行没有冒充重跑Java。Gold200/200，六组真实证据审计及冻结字节检查通过。原始结果、JSONL和运行日志与[manifest](../reports/generation-mode-matrix-20261116/manifest.json)按原字节归档；演示稿等非保护路径使仓库标为DIRTY，如实保留，不影响保护输入冻结的核对。

选择交替三轮而非只看开发单轮，是为了让收益和代价都显现：开发仅下降1分并通过筛选，正式下降3.67pp而被否决。没有采用关闭全部护栏、删掉难题或修改Gold的替代办法。没有放宽门槛挽救候选。

面试追问一：“P95降到1.5秒为什么不发布？”答：阶段门禁是速度、准确率、完整成本与有界资源同时满足；复杂题语义退化会让快速错误的答案更危险，不能用速度换掉准确率门槛。

面试追问二：“模型用temperature=0，为什么仍要三轮？”答：供应商模式、后端、负载和缓存会变；当前DeepSeek说明思考模式忽略温度，关闭思考也不等于绝对确定性。固定输入与模式快照、记录每轮波动，比口头保证确定性可信。

影响范围：只新增生成模式可选配置和审计能力；生产默认仍不发reasoning_effort，未采用全局none，未修改Gold、检索、澄清、纠错、输出上限或SQL安全护栏。下一步仍限阶段3，可在dev100单独筛选low思考强度；若无净收益就保留默认，不能直接在已见eval上打补丁追分。阶段1独立盲测、阶段2完整语义契约、阶段4受控演示仍未完成，整体目标保持进行中。
