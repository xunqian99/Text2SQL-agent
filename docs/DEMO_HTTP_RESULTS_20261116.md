## 三项失败及归因

1. **T4-003：SQL能执行，NULL口径漏掉。** Gold按非空类目聚合，共73行；实际SQL缺`WHERE product_category_name IS NOT NULL`，返回74行，多出NULL类目。COUNT DISTINCT及主关联存在，不能归为全部Join失效。额外orders关联与LIMIT100本轮未改变既有73类结果，不因此放过NULL差异。这是生成/输出语义缺口，不是超时或评估器坏了。
2. **T5-002：模型阶段超时。** HTTP15,014ms、内部15,008ms，其中MODEL15,007ms，终态REQUEST_TIMEOUT，1次模型调用、未知usage1。没有SQL结果，没有进入会话历史，`demo20-T5-002`存在但turnCount=0。主要耗时发生在模型阶段；这条观测不证明全部复杂题都慢，也不证明把预算增大就能获得正确答案。P95优化暂缓，当前只记录。
3. **T6-003：明确分母仍被澄清。** 原题已写“下单2次及以上的用户占全部下单用户的比例”，规则仍问分母。当前hints是“两次及以上/分母/注册满/有效订单”，归一化只去空白，不等价识别“2次及以上”或“全部下单用户”。它是词面规则覆盖不足，不能把这个失败归给模型；本题模型调用0，费用0。后续需按通用语义边界修复并覆盖反例，不能只加题ID特判。

会话轮数失败不等于已经发生串话；本轮两个可区分主题的追问均正确。反过来，追问正确也不能掩盖超时记录丢失。本次仅验证顺序交错，不证明同会话并发安全或多租户隔离。

## 技术与设计导读

### 1. 具体请求与来源追踪

订单数会话先问2018年订单数，GMV会话先问2018年含运费GMV/不含运费销售额；随后分别发送相同的“那2017年的呢？”。服务由sessionId定位各自上一轮，改写为完整2017问题，复用各自Schema，生成/校验/只读执行后分别返回一个计数和两个金额列。返回的sessionId、rewrittenQuestion、schemaReused与Gold结果同时验收，避免仅凭改写文本含2017就判断正确。

每次HTTP响应中的budget.requestId是模型账目身份，callNumber是该请求内调用序号；用两者将改写、生成、纠错和超时槽位关联到逐题记录。不会按时间窗口粗略求和，也不会把未采用调用抹掉。源代码树、原题库文件、协议、个人配置分别记录指纹；协议先于模型调用提交。个人配置只保存哈希，不公开正文。

### 2. 组件、公式与安全边界

`DemoHttpAcceptanceProbe`是test目录里的显式Java工具，不随mvn test付费运行。`freeze`通过SqlExecutor只读执行Gold；`run`仅向固定127.0.0.1 HTTP入口发请求；`summarize`沿用ResultNormalizer比较真实响应并核对调用账目。启动器新增CallLogDir参数，隔离本轮日志，不改变模型行为。

成本按`hit/1000×hitPrice + miss/1000×missPrice + output/1000×outputPrice`逐调用计算，并要求hit+miss=input、input+output=total。P95按全部20次HTTP墙钟排序取第19个值，失败不剔除。这里不改变表来源标记、0.4关系衰减、Top-K或桥接上限；验收工具只读生产链路的结果。

结果规范化对数字与日期做已有展示兼容，不验证列单位和完整业务契约；85%只是该样本上的结果等价比例。Gold是冻结时该库的快照，不是全库不可变版本，不能借本轮宣称跨库泛化或生产正确性。

### 3. 收益

取得20条完整HTTP证据、两条不同主题追问和一份能解释未知费用的账目；从静态测试推进到可观察的运行验收，实际暴露超时历史缺口与澄清误报。没有优化准确率、延迟或费用，不为未修复问题编造收益。

### 4. 取舍与面试预演

选择固定各层前三条而非挑历史成功题；样本量小，但来源和选择过程透明。选择复用Java结果比较器而非额外写一套评分；归一化边界保持一致，人工语义仍需另验。

**问：为什么18次SUCCESS只有17次正确？** HTTP成功只证明SQL通过并执行，NULL类目使结果口径偏离Gold；必须保留业务结果比对，不能用运行成功冒充准确率。

**问：超时不是已经返回了，为什么会话还有问题？** 返回由外层RequestBudgetRunner完成，历史写入在内部工作线程的末尾；预算打断使该末尾未执行。需要让最终对外终态和会话记录拥有一致的收尾机制，还要防晚到线程重复追加。增加超时秒数不能修复这个数据一致性缺陷。

### 5. 后续验收顺序

保留本轮原始失败。下一步先修超时会话终态记录，通过超时、首答回退、晚到工作线程和跨会话契约；不做P95优化。之后推进隔离新库初始化/运行复现，以及访问控制/限流/费用门禁。NULL契约和澄清语义继续列为明确缺陷，不能因本机链路能跑而宣布全项目完成。无需用户重新配置Key。
