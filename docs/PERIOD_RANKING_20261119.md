# 相邻自然周期与稳定排名契约（2026-11-19）

候选`p21-period-ranking-v21`只修改系统规则8、13。独立100题复核暴露稀疏月份LAG错误、截断并列任取、完整支付身份缺失后，本批补齐通用契约；没有题号分支、没有更换检索算法、没有改原v2参考。它仍是生成提示契约，不是能证明任意SQL满足业务含义的AST校验器。

## 1. 核心机制与数据流

请求：“2016年10至12月每月订单量，比上个月增加多少？区间内没有订单计0。”先确定月份身份与要求区间，按自然月聚合；日历补出11月的0后，12月1笔与11月相减为+1。不能让LAG跳过11月而用10月324笔，得到-323。若要求从2017年1月展示，12月历史仍可作为基期，不能先删历史再误报首月无基期。多维统计按完整非时间分组身份分别比较。

零和未知必须分开：日历行来自请求；事实行来自事件聚合；覆盖证据来自明确用户定义或数据覆盖信息。事件MIN/MAX只说明边界，不能证明中间数据完整。明确无事实计0或覆盖已证实时空计数才补0；缺覆盖/缺金额/缺均值保持NULL。完整年份请求不得因无事实而删除月份；源表空且未指定范围时也不能凭空造日期。系统目前没有通用数据覆盖目录，不能夸称自动识别任意数据断档。

请求：“金额最高的两组”。先按最终展示精度计算金额排序，只有金额相等时才比较完整身份元组；例如z=100、a=90、b=90，选z、a，身份不能将a、b挤到100前面。默认最多N行，候选不足不补行；用户明确原始精度排名可覆盖默认。要求前N名含并列时按`RANK<=N`，前N档不同值用`DENSE_RANK<=N`；判断并列的窗口仅含业务指标，身份只负责最终稳定展示。数值最值排除该属性未知的候选，全未知无可确认最值；这不允许过滤其他指标的事实全集。最大降序、最小升序。

## 4. 设计权衡与面试答辩

没有用SQL文本替换自动补日历、添加并列键或删除NULL。任意查询有多种事实粒度和分组范围，盲改可能损坏正确SQL。当前先约束生成并用独立参考验收；软约束未服从仍会实测失分。

问“为什么不用上一行算环比”：窗口函数理解排序行，不理解相邻月份；必须先按自然周期对齐并证明零值与未知的区别。问“为什么不把身份放进RANK排序”：那会把业务同分拆成不同名次；排名键与稳定展示键职责不同，名次确定后再按身份展示。

本批无用户必须操作事项。用户应能复述：日历/事实/覆盖三个来源如何流转，模型新增费用为0，当前验证覆盖提示契约而非整体准确率。阶段2未验收，阶段3继续暂缓。
